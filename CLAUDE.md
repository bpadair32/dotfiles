# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal dotfiles repository for a Linux/Wayland desktop environment. Configurations are organized by tool, mirroring the `~/.config/` structure. Manual symlink-based deployment (no install script).

## Key Tools Configured

- **Shell**: Zsh with Antidote plugin manager, Powerlevel10k prompt
- **Editor**: Neovim using LazyVim framework with extensive language support (Python, Terraform, Ansible, Docker, Helm, YAML, JSON, SQL)
- **Terminal**: Kitty, Tmux (with TPM plugin manager)
- **Window Manager**: Hyprland (Wayland compositor) with Waybar, Rofi, Dunst, Swaync
- **Dev Tools**: Lazygit, fzf, fd, bat, eza, ripgrep, zoxide

## Architecture

**Shell initialization chain**: `zshrc` → Antidote → plugins → `alias.sh` → `functions.sh` → `greeting.sh`

**Neovim structure** (`nvim/`):
- LazyVim base configuration in `lazyvim.json`
- Custom plugins in `lua/plugins/` (each file auto-loaded by lazy.nvim)
- Language extras defined in `lazyvim.json` under `extras`

**Hyprland structure** (`hypr/`):
- Main config sources modular files from `$configs` directory
- Separate files for monitors, keybinds, window rules, colors
- Related configs: `hyprlock/`, `hypridle.conf`

**Tmux plugins**: Managed by TPM in `tmux/plugins/`, loaded via `tmux.conf`

**Theming system** (`themes/`, `templates/`, `scripts/theme-switch`):
- Static themes defined in `themes/<name>/theme.toml` (TOML format with Material Design 3 color tokens)
- Templates in `templates/*.tmpl` generate tool-specific configs via envsubst
- `scripts/theme-switch` applies themes and reloads applications
- Supports pywal (`--pywal`) and matugen (`--matugen`) for dynamic wallpaper-based theming
- All three sources (static, pywal, matugen) converge on the same `theme.toml`
  format and run through `apply_theme`, so they reach identical targets.
  Matugen's config in `matugen/` holds exactly one template, which writes that
  `theme.toml`; it does not generate app configs directly.

Theme targets: Hyprland (+hyprlock), waybar, wlogout, swaync, dunst, kitty,
rofi, GTK3/GTK4, Qt via qt5ct/qt6ct, KDE apps via `kdeglobals`, SDDM, Neovim
(colorscheme name only), btop, tmux, lazygit, k9s, yazi, rmpc, Firefox and Zen
(userChrome/userContent), and Obsidian (CSS snippet per vault).

Zen needs `templates/zen-colors.css.tmpl` appended after the shared Firefox
rules: it redefines the standard chrome variables with `!important`, but derives
its whole palette from `--zen-primary-color` and `--zen-branding-dark`, so those
two are what to set. Its accent also lives in a pref (`zen.theme.accent-color`),
written to the profile's `user.js`.

## Working with This Repo

When editing configurations:
- Neovim plugins go in `nvim/lua/plugins/` as individual Lua files
- Shell aliases belong in `alias.sh`, functions in `functions.sh`
- Hyprland keybinds are in `hypr/configs/keybinds.conf`, not the main config
- Color files (`hypr/colors.conf`, `waybar/colors.css`, etc.) are generated by `theme-switch` - edit themes instead
- `lazygit/config.yml` is fully generated too; add lazygit settings to `templates/lazygit-config.yml.tmpl`

When working with themes:
- Create new themes in `themes/<name>/theme.toml` with Material Design 3 color tokens
- Use `theme-switch <name>` to apply, `theme-switch --list` to see available themes
- Dynamic themes from wallpaper: `theme-switch --matugen <image>` or `theme-switch --pywal <image>`
- Keybind: `Super+Ctrl+T` opens rofi theme selector

Git excludes hardware-specific configs (`hypr/monitors.conf`), plugin directories, and dynamic themes (`themes/_dynamic/`).
